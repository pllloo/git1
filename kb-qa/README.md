# 个人学习笔记问答系统（RAG 检索对比与评测）

用自己的 Markdown 学习笔记做问答：只根据检索到的片段回答；片段里没有就明确说「笔记中没有相关内容」。

面向个人笔记，不是通用搜索引擎。默认检索走本地向量，不把笔记发到付费 Embedding API。

**技术栈：** Python · RAG（切分 / 向量检索 / Prompt）· fastembed + `bge-small-zh-v1.5` · DeepSeek

---

## 怎么运行

依赖 `hello-agents`（`hello_agents`）和根目录 `.env` 中的 DeepSeek 配置。在该虚拟环境中运行 `kb_qa_v1.py`。首次运行会下载 `BAAI/bge-small-zh-v1.5`。笔记目录由代码里的 `NOTES_DIR` 指定。

```powershell
python kb_qa_v1.py
```

## 架构

```
笔记 md（01–10 号，约 42 块）
    → 按换行后的 ## 切块
    → 本地 embedding（512 维）
    → 问题向量与每块算余弦相似度，取 top-2
    → 两块拼进 prompt，要求「没有就说没有」
    → DeepSeek 生成
```

Embedding 为本地 `fastembed` + `bge-small-zh-v1.5`（512 维），不把笔记发到付费接口。启动时为全部块建一次向量，之后每次提问只向量化问题。

另有一条关键词基线：按题目实词在块中的出现次数排序，取 top-2，只用于对比。检索前也可先把问题改写成短查询，再做向量检索；生成仍用原问题。

## 对比实验：关键词 vs 语义

**命中：** 事先指定的应召回块是否出现在 top-2 中，不看最终回答是否通顺。

6 题（不含「量子力学」「MCP」：库中无应召回块或未入库）。

| 策略 | 命中 |
|---|---|
| 关键词（实词出现次数） | **4/6** |
| 语义（余弦 top-2） | **3/6** |

| 题 | 关键词 | 语义 |
|---|---|---|
| git 怎么推送 | 命中 | 命中 |
| 学过哪些正则 | 命中 | 命中 |
| 正则 r 前缀 | 命中 | 命中 |
| 总结全部笔记 | 未命中 | 未命中 |
| 双记忆机制 | **命中** | 未命中 |
| LangChain vs LangGraph | 未命中 | 未命中 |

语义失败例：「双记忆机制」召回到 memory_tool / rag_tool，而答案在 08 笔记的「工作记忆 vs 长期记忆」。  
关键词失败例：「对比 LangChain 和 LangGraph」只召回了 LangChain 一边。

不是语义全面更好：题里已经有笔记用词时，关键词可能更准。

---

## 查询改写

检索前可用一次 LLM，把原问题收成短查询，再用短句做向量检索。生成仍用用户原话。

同一 6 题上，改写后语义命中仍为 **3/6**，没有提高。改写请求里没有笔记内容，模型无法把「双记忆」换成笔记里的「工作记忆 / 长期记忆」，短查询接近原句，召回块不变。`git怎么推送` 能改成 `git push`，是因为提示词里给了这个例子。

## 失败案例（分层）

| 问题 | 层 | 原因 |
|---|---|---|
| 帮我总结所有笔记 | 召回 | `top_k=2`，不可能覆盖 42 块 |
| MCP 是什么 | 召回 | 11 号笔记在磁盘上，但 `NOTE_FILES` 只到 10 号 |
| 对比 LangChain / LangGraph | 召回 | 该进 top-2 的块没进；不是幻觉（模型没有编区别） |

切分有一处已知问题：` ## 续Day2` 前多了空格，`split("\n##")` 未切开，r 前缀与「旅游助手」落在同一块。

---

## 局限

- 笔记白名单未包含 11 号及以后，MCP 等后续内容检索不到。
- 默认只取 2 块，不适合「总结全部」。
- 查询改写请求不包含笔记正文，无法替换成笔记里的专用说法。
